# BorderFlow 技術報告

## 1. 系統與資料

Laravel 12 負責路由、資料驗證、Session、CSRF 與 API。頁面以 Blade 和原生 JavaScript 實作，圖表使用 SVG。MySQL 8.4 管理主資料、每日彙總、示範交易、配額及稽核。Docker Compose 提供本機執行環境。

關聯結構：

- checkpoint → checkpoint_alias、daily_traffic、crossing、simulation
- traveller → crossing
- quota_day → quota_slot → booking → booking_audit
- daily_traffic → demo_reconciliation

各資料表使用 InnoDB。每日資料的唯一鍵為口岸、日期及方向。匯入器驗證總量等於居民、內地訪客與其他訪客之和，遇到未知口岸名稱時建立口岸別名。澳門碼頭的 Macau 和 Macao 寫法映射到同一主鍵。歷史日期使用官方 CSV 所載的資料列。

## 2. 配額與狀態

應用以交易依序更新日配額、時段配額與預約。配額更新條件為 reserved < capacity，任一更新失敗便回滾。MySQL CHECK 保護計數上限，生成欄位配合唯一鍵限制同車同時段重複預約。觸發器限制狀態轉移並寫入稽核。取消依照同一順序釋放兩層配額。演示規則由帶有生效日期的資料表控制，2025-09-01 版本排除週二及週三。

## 3. 排隊模型

每分鐘到達量等於基準到達量加上逐步升至目標的增量。每分鐘完成量受隊列和通道容量限制。隊列為上分鐘剩餘加到達減完成，等候時間以剩餘隊列除以每分鐘容量估計。到達量低於容量時隊列可縮短，超過容量後會積累，因而具有不同的增長區間。模型用於情景比較。

以 2026-11-07 入境統計為例，未使用日期索引時掃描 75,304 列，聚合約 14 ms。使用日期索引時讀取 14 列，聚合約 0.044 ms。這是單次測量，耗時受環境及快取影響。

## 5. 已實作範圍

參考層涵蓋官方每日、節日和口岸等候來源。明細生成以選定的口岸、日期與方向對帳，以控制示範資料庫大小。旅客的人工覆核備註使用固定虛構案例。公眾端提供口岸比較和接駁方式。進階起訖路線規劃、簽證申請工作流、具名帳戶管理及其餘補充資料集仍屬後續範圍。
